# GSoC 2027 Guided Study Plan

This plan is a starting point and will be adjusted based on learning progress and the requirements of organizations we shortlist.

## Study routine

- Target: 45–60 minutes per day, 6 days per week.
- One lighter review/rest day each week.
- Learn one concept, practise it, explain it in your own words, and record mistakes.
- Do not chase certificates or artificial GitHub activity. Prioritize genuine understanding and useful work.

## Initial direction

C++ is the first language for focused practice because it is the language currently being explored for GSoC organization options. This is provisional: the final primary language and project direction must match real organization codebases and project requirements.

Python remains a useful secondary skill and supports the longer-term AI/ML goal. We will add it to the routine without splitting attention too early.

## Daily 60-minute structure

1. 25 minutes — lesson and examples.
2. 20 minutes — coding/practice task.
3. 10 minutes — explain the concept or solve a review question.
4. 5 minutes — update the daily log.

On busy college days, use the 30-minute version: 15 minutes learning, 10 minutes practice, 5 minutes log.

## First four weeks

### Week 1 — Workflow and fundamentals
- Git, GitHub, repositories, commits, branches, push and pull.
- Refresh C++ functions, arrays, strings, references, pointers and STL basics.
- Learn how to compile, run, debug and read compiler errors.
- Complete small practice programs.

### Week 2 — Problem solving and code quality
- C++ STL: vector, map, set, stack, queue and algorithms.
- Basic time and space complexity.
- Solve beginner problems and explain the approach before coding.
- Learn to write clear README files and useful commit messages.

### Week 3 — Open-source workflow
- Understand issues, pull requests, forks, branches and code review.
- Read contribution guides and set up one small real repository locally.
- Learn to reproduce a bug, run tests and make a small documentation or code improvement.

### Week 4 — Organization exploration
- Shortlist organizations only after checking official GSoC information.
- Inspect their repositories, languages, recent activity, contribution guides and community channels.
- Compare project ideas against current skills.
- Choose one or two organizations for deeper exploration.

## Weekly review

At the end of each week, record:
- Concepts understood
- Programs/tasks completed
- Errors and gaps
- Repository or open-source work attempted
- Next week's three priorities

## Rules for tracking

- A topic is not complete just because a video was watched. It is complete when the learner can explain it and solve a small task independently.
- Record actual work only. Never invent contributions, PRs or progress.
- Keep credentials and tokens out of this repository.
- Verify GSoC dates, eligibility and organization participation on official sources; these can change each year.
